## 建议检查顺序

1. 先看 matrix 的一组 shared context、输入分组／reference、HDR reliability 与 motion
   传播语义；这决定两个轴是否有一致的颜色／曝光意义。
2. 看 standalone HDR 的 radiance／partial clipping／motion 数值，以及 matrix
   source／confidence／clipping／deghost maps。不同阶段 fraction 不能直接相乘。
3. 看首次失败的 static Gaussian case：v1.8 高亮 case 内部 false-motion 30.44%，
   v1.8.1 为 0；普通亮度对照与真实时间变化同时保留。修复依赖受限 blur 解释，
   没有调高 motion threshold。
4. 看 native budget／wall／RSS／scratch，再用统一显示变换检查全图和细节；PNG
   是 preview，原始 scene-linear TIFF 才保存 HDR／signed samples。

本机生成的照片与检查材料保存在忽略的 `build/`，不把大量 RAW／TIFF 提交 Git。
新复现工具保留 DNG／truth／代码快照、binary hash、数字结果与预览；可以重建检查，
不依赖仅留在会话里的截图。详细命令见上表链接。
